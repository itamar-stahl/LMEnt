\section{Experimental Design}
\label{sec:experimental-design}

\subsection{Models and Matched Training}

We trained OLMo-2 1B models on LMEnt's entity-annotated Wikipedia corpus
\citep{walsh2025olmo2,gottesman2025lment}. The shared full model received
loss on the full corpus. For each target concept, we trained a
concept-excluded twin from the same initialization, using the same batch
order, optimizer, learning-rate schedule, and two-epoch duration. Exclusion
was applied after batch construction: labels in selected chunks were masked
so that those chunks contributed no training loss. Each twin therefore
differed from the full model in the learning signal from its selected
chunks, while the configured training procedure remained matched.

\subsection{Concepts and Exclusion Sets}

We selected Ancient Rome, Baseball, and artificial intelligence (AI)
purposively. Preliminary accuracy of the full model on target selection
questions helped us avoid concepts with little measurable knowledge; we also
sought manageable breadth and variation across domains. Results on these
three concepts may not generalize to other concepts.

For each concept, we used Claude in a dedicated session to propose
Wikidata entity IDs (QIDs) \citep{vrandecic2014wikidata}, then reviewed their
coverage in LMEnt's corpus \citep{gottesman2025lment}. A single ID missed text
linked to related entities, while an overly broad set risked masking loss on
text about adjacent topics. We therefore selected a bounded set of QIDs for
each concept. We masked the loss on a training chunk if LMEnt linked at
least one mention in it to a selected QID. Table~\ref{tab:exclusion-sets}
reports the resulting ID counts, unique excluded chunks, and corpus shares.

\subsection{Post-Training Erasure and Checkpoint Selection}

We applied EMBER, RMU, and an SNMF-based erasure independently to copies of
the completed full model for each concept. We also evaluated RMU+EMBER and
SNMF+EMBER. For each ensemble, we fixed the selected EMBER checkpoint and
then applied the MLP method to the edited model, following EMBER's staged
ensemble design \citep{suslik2026ember}. EMBER modified selected input
embeddings, whereas RMU and SNMF edited MLP weights. For both ensembles, we
reran the MLP method's model-dependent setup on the EMBER-edited model. We
used the same method definitions and checkpoint-selection rule for every
concept.

EMBER's factorization produced candidate semantic features from target and
neutral sentences. We used \texttt{google/gemma-4-12B-it} as a semantic judge
\citep{gemmateam2026gemma4}
to inspect each candidate's activating tokens and contexts, retaining features
that it classified as representing the target concept with confidence of at
least 0.85. This judgment determined which embedding directions EMBER edited;
Appendix~\ref{app:ember-feature-selection} records how the selections were
reproduced in the final runs.

We evaluated 97 candidate checkpoints: 30 for EMBER, 24 for RMU,
10 for SNMF, 24 for RMU+EMBER, and 9 for SNMF+EMBER. We selected one
checkpoint for each method and concept using
likelihood-ranked accuracy on the selection splits described in
Section~\ref{sec:evaluation}. Selection used target questions,
neighboring questions, and a shared general-capability set drawn from
SciQ \citep{welbl2017sciq}. The concept-excluded twins and all test questions
were withheld from this procedure.

We selected the candidate with the largest accuracy-based
$H_{\mathrm{selection}}$ defined in Section~\ref{sec:evaluation}, using a fixed
deterministic order to break exact ties. Initially we tried to use an NLL-based criterion we designed ourself but we forfeited the idea 
because, for EMBER, it increased monotonically with edit strength and selected
the edge of the grid. The selection score adapts EMBER's validation rule to our base-model setting
\citep{suslik2026ember}: neighboring-topic questions measure specificity, and
SciQ replaces MMLU as the general-preservation benchmark. We omitted
AlpacaEval coherence because our model was not trained to follow instructions;
low scores could therefore reflect this baseline limitation rather than
erasure-induced degradation. All checkpoint choices used only the selection
split. We then evaluated the 15 selected checkpoints against the full model
and the corresponding concept-excluded twins on the held-out test split.
