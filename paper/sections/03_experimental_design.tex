\section{Experimental Design}
\label{sec:experimental-design}

\subsection{Models and Matched Training}

We train decoder-only OLMo-2 1B base models with 18 layers, hidden size 2048,
and 16 attention heads on LMEnt's 3.6B-token Wikipedia corpus. All models train
for two epochs (54,832 optimizer steps) with global batch size 131,072 tokens,
AdamW, peak learning rate $4\times10^{-4}$, 2,000 warm-up steps, and cosine
decay to $4\times10^{-5}$. The initialization seed is 12536 and the data seed
is 0.

The shared control receives loss on the complete corpus. Each concept-excluded
arm starts from the same seeded initialization and uses the same optimizer,
schedule, batch indices, and number of steps. Exclusion is applied only after a
batch has been composed: a matched chunk keeps its batch position, but every
label in that row is replaced with the ignore index. It therefore contributes
neither loss nor gradient. One control is shared by the Ancient Rome and
Baseball arms.

\subsection{Concepts and Data Removal}

LMEnt associates chunks with candidate Wikidata entities derived from
hyperlinks, entity linking, coreference, and coreference clusters. We resolve a
manually audited set of QIDs for each target and mask chunks passing the source
specificity thresholds. Ancient Rome uses 56 entities and covers 65,844 chunks
(0.628\% of the corpus). The final set replaced an initial one-entity blacklist
after a corpus audit showed that it captured only a small fraction of sampled
Rome-bearing passages. The expanded set was estimated at approximately 46\%
coverage and 62.5\% precision on that audit.

Baseball uses 43 entities covering 80,466 chunks (0.766\%): core baseball
institutions and the 30 Major League Baseball franchises. Teams were included
after a corpus-only audit: the core set achieved 94.0\% estimated precision and
43.1\% coverage, while adding teams raised estimated coverage to 56.5\% at
87.2\% precision. Adding a player set produced only 0.1 percentage points of
additional coverage while reducing precision, so it was rejected. The tracked
configuration records that this choice preceded the question-answering
evaluation.

These definitions deliberately favor an auditable intervention over an
unverifiable claim of complete removal. Unlinked Roman context and general
baseball rules may remain elsewhere in the corpus. We therefore treat the
excluded model as the target induced by this particular data operation.
Pornography experiments are outside the scope of the main study.

\subsection{Erasure Methods}

All post-hoc methods begin from the completed shared control checkpoint.

\paragraph{EMBER.}
We factorize its embedding matrix at rank 100 with global sparsity 0.02 and seed
44. Candidate features are ranked by their activation ratio on 300 concept and
300 neutral sentences and filtered by a Gemma-4-12B-IT judge at confidence
threshold 0.85. For Ancient Rome, the factorization-cell rule prioritizes judge
confidence and then activation ratio and was fixed before the grid was complete.
The Baseball cell was likewise selected on feature quality before erasure, but
its detailed selection note is stored only on the cluster. Neither choice used
the concept-excluded outputs. Ancient Rome selects feature 11 and edits 76
embedding rows; Baseball selects feature 10 and edits 72. In both cases the
untied output head and all other tensors remain unchanged.
The candidate edit strengths are
$\{0.5,1,2,5,10,50,100,200\}$. EMBER chooses a delta using efficacy on 50
concept-training questions and accuracy-based specificity on 50 neighboring
domain training questions. The held-out halves are not used for delta
selection. This chooses 200 for Ancient Rome and 10 for Baseball.

\subsection{Implementation and Validity Checks}

Training logs confirm that each blacklist was loaded and that Baseball incurred
zero all-masked-batch guard leaks across its five training windows.
\placeholder{Confirm and report the same final guard-leak statement for Ancient
Rome from archived logs.} Converted checkpoints were checked for tensor count,
shape agreement, tokenizer identity, and healthy embedding statistics. EMBER's
materialized checkpoints were independently compared with the control to verify
that exactly the reported embedding rows, and no other parameters, changed.

The sparse factorization is sensitive to the numerical environment: the same
Rome cell reproduced byte-identically on two RTX 3090 nodes but produced a
different feature set on an A6000. The erasure jobs therefore reused the
selected grid caches rather than refitting them. This makes the completed edits
correspond to the judged features, while limiting reproducibility claims to the
archived feature artifacts and recorded environment.

The tracked YAML configurations have identical \texttt{train} blocks; for
Ancient Rome they differ from control only in the job name and exclusion block,
while Baseball additionally changes scheduling fields. Run summaries record
the same final step and core recipe. The archived run-local configuration and
environment files are not present in this repository, so exact resume-lineage
identity remains to be checked from cluster artifacts.

Some training windows resumed on a different accelerator type. The control's
last 9.7\% of updates and Baseball's last 2,832 updates ran on an H200 rather
than an H100. A diagnostic measured small cross-device drift, but this remains
a qualification for directional weight-space comparisons.
