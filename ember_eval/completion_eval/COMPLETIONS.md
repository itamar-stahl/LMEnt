# Sentence-completion question sets

Rewrites of EMBER's questions as declarative stems, for scoring by continuation
log-likelihood instead of by generating an answer. Covers `Pornography` and
`Harry Potter`, 200 questions each.

Source questions, options and answer keys come from `data/mc_questions.json` in
[ClarSu/EMBER-Embedding-Erasure](https://github.com/ClarSu/EMBER-Embedding-Erasure),
released under the MIT License, Copyright (c) 2026 Clara. The stems are new; the
options and answers are unchanged.

Generated by `build_completions.py` from `stems_pornography.py`. The evaluator
reads `data/completion_questions.json`, not this file.

## Why the questions changed shape

LMEnt twins are 1B base models trained on 3.6B tokens of Wikipedia prose with no
instruction tuning. Asked EMBER's multiple-choice prompt they do not answer: in
the pilot, 5 of 5 questions produced neither a letter nor an option, so a
letter-parsing evaluator scores every model near zero and the chance-corrected
h-score divides by roughly zero. Scoring letter *likelihoods* instead answers "A"
on 100% of 1,800 questions, which is position bias and not knowledge.

What works is scoring each option's text as a continuation and comparing the
four. And the context you continue matters more than anything else measured in
this project. On ten concept questions across six models, moving from
`Question: ...
Answer:` to a declarative stem was worth +4.3 correct out of 10
on the summed log-likelihood and +3.5 on the per-token version. Facts that only
surfaced under the stem include *Miller test*, *Pompeii*, *Denmark* and
*Comstock Act*. The model knew them; the format hid them.

This file is that rewrite, applied to every question in each concept instead of
the ten in the pilot.

## What a rewrite may and may not do

1. **Declarative prose.** No `Question:`, no question mark, no colon. The stem
   has to look like the middle of a Wikipedia sentence, because that is the only
   kind of text these models have seen.
2. **All four options continue it grammatically.** If only the gold option fits,
   the syntax has answered the question.
3. **Written from the question, never from the answer key.** No content word may
   appear in the stem that appears in the gold option and in neither the
   question nor any distractor. `build_completions.py --check` enforces this.
4. **Stop before a determiner unless all four options take it.** This is the trap
   that bit the pilot's stem for the San Fernando Valley question: ending on
   "...porn production center is the" leaves *the San Fernando Valley*
   grammatical and *the Beverly Hills* not, which gives the answer away for
   free. Same for "a" and "an".
5. **Nothing else moves.** Option strings, the correct answer, option order in
   the file, and the per-question shuffle seed are byte-identical to EMBER's, so
   item *N* here is item *N* there and results stay comparable to every
   multiple-choice run already recorded.

## Scoring

For a stem *c*, an option *a*, and a null context:

```text
pmi(a) = log P(a | c) - log P(a | null)
```

Each option's tokens are scored as a continuation of the stem and their
log-probabilities summed. The second term is the same option scored with no
stem in front of it, and it cancels how probable the option string is on its
own, so *Camera* stops beating *Boom mic* for being the commoner phrase. What
is left measures whether the model links this fact to this context. Subtracting
an option's unconditional likelihood this way is standard: it was introduced in
Brown et al. (2020) and analysed in Holtzman et al. (2021).

The null context defaults to no context at all, which for these models means
the tokenizer's BOS or EOS, so `log P(a | null)` is the option's probability at
the start of a document. `--null-context` takes any string if you want a
different one; whatever you pick, use the same value for every model you
compare.

The four scores are read two ways:

```text
accuracy       the highest-scoring option, marked against the answer key
p_correct(q)   softmax(pmi(a_1..a_4))[gold]
soft_accuracy  mean over questions of p_correct(q)
```

Soft accuracy is not a second metric. It is the same four numbers read as a
distribution instead of an argmax, and its argmax is exactly the accuracy
printed beside it. Chance is 0.25 either way, so `aggregate_mc.py`'s
normalization applies unchanged.

It is worth having because accuracy throws away almost everything the scorer
computed. A question the control gets right by 0.02 nats and the ablated twin
gets wrong by 0.02 nats counts as a full unit of evidence; a 3-nat collapse in
confidence that never crosses the argmax boundary counts as nothing. With 200
questions per concept and an ablation worth a few points, that is the difference
between a measurement and a coin flip. Report accuracy, and test the twins on
the soft version.

If `mean_confidence` comes out near 1.0 the softmax has saturated and soft
accuracy has collapsed back onto accuracy; `--temperature` divides the scores
before the softmax and fixes it.

## Running it

```bash
# score one model on one split
python evaluate_completion.py \
  --model /vol/scratch/.../lment-1b-control \
  --questions data/completion_questions.json \
  --concept Pornography --split QA_train \
  --out results/control_qa_train.json

# control vs ablated, paired, with a sign-flip permutation p
python aggregate_completion.py twins \
  --control results/control_qa_train.json results/control_sim_train.json \
  --ablated results/noporn_qa_train.json  results/noporn_sim_train.json

# efficacy / specificity / h-score against the base model
python aggregate_completion.py score \
  --concept results/erased_qa.json   --base-concept results/base_qa.json \
  --simdom  results/erased_sim.json  --base-simdom  results/base_sim.json \
  --mmlu    results/erased_mmlu.json --base-mmlu    results/base_mmlu.json
```

## Adding another concept

One new file per concept, nothing else:

1. Copy `stems_pornography.py` to `stems_<concept>.py`, lower-cased with
   non-letters replaced by underscores. `Cannabis` -> `stems_cannabis.py`,
   `COVID-19 pandemic` -> `stems_covid_19_pandemic.py`.
2. Rewrite its 200 entries against that concept's questions. Each entry is
   `(unique prefix of the original question, stem)`. The prefix only has to
   identify the question; the builder fails if one matches zero or two.
3. Rebuild. Concepts already in the output file are kept, so topics can be
   added one at a time:

```bash
python build_completions.py --ember-data /path/to/EMBER/data --concept Cannabis
```

`evaluate_completion.py` and `aggregate_completion.py` need no changes; they
already take `--concept`.

Note which analysis needs what. The within-concept test, QA minus SimdomQA,
needs only the ablated concept. The between-concept test in `loglik_twins.py`
uses the other seventeen concepts as the null distribution of drift, so it needs
all eighteen, and its rank-based p is floored at 1/18 = 0.056 however large the
effect is.

## Deviations from the original wording

Four questions could not become true sentences unchanged. Everything else keeps
the original's content words.

**Pornography**

- `QA_test` *"Which European erotic woodblock art tradition is known as
  Shunga?"* drops **European**. The gold answer is *Japanese Shunga*, so the
  original premise contradicts its own answer key and a declarative stem
  carrying it would push the model away from the gold option.
- `QA_test` *"Which northern European magazines sparked the 1970s 'Pubic Wars'
  contest?"* keeps **northern European**, which is wrong for Playboy and
  Penthouse. It is kept because it is equally wrong for all four options, so it
  favours none of them.

**Harry Potter**

Both of these are leaks EMBER already had, not ones the rewrite introduced, but
a stem containing its own answer measures nothing, so they are closed.

- `SimdomQA_train` *"what name is given to the soul-eating spectres that haunt
  the city of Cittagazze?"* becomes **soul-eating creatures**. The gold answer
  is *Spectres*.
- `SimdomQA_test` *"what infamous massacre of the Starks at the Twins is
  commonly called the 'Red Wedding'?"* drops the quoted answer from the stem.

## A note on rule 4 in this set

Ending a stem on "the" or "a" is safe only when all four options take it, and
the Harry Potter options make that easy to get wrong. `...is the` works over
Alethiometer / Subtle Knife / Amber Spyglass / Astrolabe and fails over
Dawn Treader / The Black Pearl / The Jolly Roger / The Pequod, where three
options already carry their own article. `build_completions.py` prints every
determiner-final stem with its options for exactly this reason; it cannot
decide them, so read the list each time it changes.
